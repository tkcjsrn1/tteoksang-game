# 학술제 모드 만들기 — 인수인계 문서

이 문서는 **학술제 모드를 대신 만들어 줄 사람**을 위해 쓴 것입니다. 이것만 읽고도 작업을 시작할 수 있게 적었습니다.

**먼저 읽을 것**

1. `CLAUDE.md` — 이 저장소의 작업 규칙. 짧습니다
2. `docs/PROJECT.md` — 목적, 구조, 가격 규칙, 결정 기록
3. 이 문서

```bash
npm ci              # Node 22 이상
npm run dev         # 서버 + 화면 → http://localhost:5173
npm test            # 커밋 전에 반드시 통과
```

---

## 1. 배경 — 왜 지웠다가 다시 만드나

학술제 모드는 **2026-11-10에 지웠습니다**(커밋 `ed2c504`). 당시 이유는 "만든 사람이 쓰지 않기로 함"이었고, 친구 대전과 혼자 연습만 남겼습니다.

그런데 **11월 25일 학술제에서 80명 규모로 쓰게 되어** 다시 필요해졌습니다.

지웠을 때 함께 사라진 것:

| 사라진 것 | 설명 |
| --- | --- |
| `GameMode`의 `'academic'` | 모드 자체 (정원 60명이었음) |
| `Role`의 `'operator'`, `'display'` | 운영자와 대형 화면 역할 |
| `client/src/Display.tsx` (50줄) | 대형 화면. 최신 뉴스·종목 등락·남은 시간·상위 5명 |
| `PredictionView`, `{ t: 'predict' }` | 결과 공개 전에 결말을 예측하는 기능 |
| `report.ts`의 과신 지표 | 평균 확신도 − 실제 정답률 |

## 2. 이미 끝난 것 — 다시 만들지 마세요

**정원 선택이 이미 들어갔습니다.** 친구 대전에서 `8 · 20 · 40 · 80명`을 고를 수 있습니다(PR #11).

- `shared/rules.ts`의 `ROOM_OPTIONS.maxPlayers = [8, 20, 40, 80]`
- 정원은 **친구 대전 전용**입니다. 혼자 연습에 보내면 서버가 400으로 거절합니다
- `tests/room.test.ts`에 **80명이 한 방에서 5라운드를 끝까지 마치는 테스트**가 있습니다. 순위 83줄(사람 80 + NPC 3), 등수·평가액 순서·현금이 어긋나지 않는 것까지 확인합니다

즉 **"80명이 한 방에서 게임을 한다"는 이미 됩니다.** 남은 것은 운영자 쪽 기능입니다.

## 3. 만들 것

### (1) 운영자 대형 화면 — 제일 중요

학술제에서 **강당 스크린에 띄울 화면**입니다. 참가자 휴대폰 화면과 다릅니다.

지워진 `Display.tsx`가 보여 주던 것:

- 대기실: 방 코드(크게), 입장 인원, **큰 QR**, 운영자만 보이는 시작 버튼
- 진행 중: 라운드 번호, 남은 시간, 최신 뉴스, 종목별 등락, **상위 5명**
- **개인 주문과 개인 자산은 절대 나오지 않습니다**

지워진 코드를 그대로 볼 수 있습니다:

```bash
git show ed2c504 -- client/src/Display.tsx
git show ed2c504 -- shared/types.ts
git show ed2c504 -- server/src/room.ts
```

**다만 `git revert`로는 되살릴 수 없습니다.** 그 커밋에 다크 모드 추가가 섞여 있고, 그 뒤로 아래가 전부 들어왔기 때문입니다.

- 난이도 쉬움·실전 분리
- 장중 1초 시세, 호가창 10단계, 슬리피지
- 손절·익절 예약
- 배당·배당락
- 한 판 종목 고르는 방식 변경(`pickStocks`)
- `Game.tsx` 1,032줄을 네 파일로 분할 (`client/src/game/`)
- 최근에 본 사건 제외
- 정원 선택

**참고용으로 읽고, 지금 코드에 맞게 다시 쓰는 쪽**을 권합니다.

### (2) 결과 예측과 과신 지표 — 선택

장 마감 전에 "이 뉴스의 결과가 기대보다 좋을까?"를 확신도와 함께 찍게 하고, 판이 끝나면 **평균 확신도 − 실제 정답률**을 보여 주던 기능입니다. 교육 효과는 좋지만 **없어도 학술제는 돌아갑니다.** 시간이 남으면 하세요.

### (3) 모드를 따로 만들 것인가

**권하지 않습니다.** 친구 대전에 정원 80명이 이미 있으므로, `'academic'` 모드를 새로 만들면 분기가 두 벌이 됩니다. 결정 기록에도 *"같은 기능이 두 벌이면 나중에 고칠 때 한쪽만 고치게 됨"*이라 적혀 있습니다.

**대신 역할(`Role`)만 추가하는 쪽**이 깔끔합니다. 친구 대전 방에 `operator`와 `display` 역할을 붙이는 방식입니다.

## 5. 반드시 지킬 것

`CLAUDE.md`에 다 있지만, **이 작업에서 특히 걸리는 것**만 추립니다.

1. **공개 전 정보가 새면 안 됩니다.** 대형 화면은 모두가 보는 화면입니다. `RoomView`에 새 필드를 넣으면 `tests/room.test.ts`의 공개 범위 테스트에 **반드시** 추가하세요. 결말·상대 주문·정산 중 가격은 절대 나가면 안 됩니다
2. **개인 정보는 대형 화면에 올리지 않습니다.** 상위 5명의 이름과 수익률까지가 한계입니다. 보유 종목·현금·주문은 안 됩니다
3. **`server/src/content.ts`를 `client/`에서 import하지 마세요.** 테스트가 막습니다
4. **금액은 정수(원, bp)로만** 계산합니다
5. **새 전문 용어를 화면에 쓰면** `shared/glossary.ts`에 넣고 `<TermLink>`로 연결합니다. 실제 시장과 다른 점은 `game` 칸에 적습니다
6. **사용자 문구는 존댓말, 짧게**, 투자 권유로 읽히지 않게. 모든 화면에 `<Disclaimer />`
7. **모르는 제도·숫자는 지어내지 마세요.** 확실하지 않으면 물어보세요
8. 큰 결정을 하면 `docs/PROJECT.md` 12절 결정 기록에 한 줄 남깁니다

## 6. 측정된 제약 — 꼭 알고 시작하세요

실제로 재 본 값입니다. 추측이 아닙니다.

| 항목 | 값 |
| --- | --- |
| 1인당 1초 전송량 | **약 6.7KB** (사람 수가 늘어도 1인당은 거의 안 늘어남) |
| 80명이면 | 매초 **525KB**, 한 판(650초)에 **349MB** |
| Render 무료 월 전송량 | 5GB → **약 14판** |
| 80명 한 방 5라운드 계산 시간 | 83ms (로직은 여유) |
| 320명 동시 주문 | 응답 중앙값 140ms, 체결 어긋남 0 |

**대형 화면은 연결이 하나 더 늘어나는 것**이라 전송량에 큰 영향은 없습니다. 다만 대형 화면에 보내는 정보를 참가자 화면만큼 자주·많이 보내면 그만큼 늘어납니다. **필요한 것만 보내세요.**

아직 **확인 못 한 것**: Render 무료 인스턴스가 80개 연결에 매초 525KB를 밀어낼 수 있는지. 실제 배포 환경에서만 알 수 있습니다. 작업이 끝나면 배포해서 여러 기기로 확인해야 합니다.

**헷갈리지 않게 덧붙이면**, VI(변동성 완화장치)는 코드에 있지만 **실제 게임에서는 한 번도 발동하지 않습니다**. 장중 최대 등락폭이 구조적으로 6%가 천장인데 VI 기준이 10%라서입니다(20,000건 측정, 0건). 대형 화면에 VI 표시를 넣을 생각이라면 알아 두세요.

## 7. 끝내기 전 확인

```bash
npx tsc --noEmit        # 타입 검사
npm test                # 전체 테스트. 반드시 통과
npm run build           # 타입 검사 + 클라이언트 빌드
npm run e2e             # 화면 자동 테스트(390px). 먼저 npm run build
npm run load 10         # 방 10개 × 8명 = 80명 동시 주문
npm run balance         # content.ts나 npc.ts를 바꿨다면
```

화면을 바꿨으면 **390px 폭에서 직접 확인**하세요. 대형 화면은 반대로 **1920px에서** 확인하면 됩니다.

## 8. 작업 방식

- `main`에 바로 푸시하지 마세요. **브랜치를 만들어 PR**로 올립니다
- 커밋 메시지는 **한국어로, 무엇을 왜 바꿨는지** 씁니다
- 기능을 바꾸면 테스트를 함께 추가합니다. 버그를 고치면 **그 버그를 재현하는 테스트부터** 씁니다
- CI가 Ubuntu·Windows·실제 PostgreSQL 세 군데에서 돕니다. 하나라도 실패하면 머지하지 않습니다
