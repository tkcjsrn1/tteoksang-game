# 떡상개론 — 프로젝트 설명서

이 문서는 사람이든 AI든 이 저장소를 처음 여는 사람이 **무엇을, 누구를 위해, 왜 이렇게** 만들었는지 이해하도록 쓴 문서입니다. 코드를 고치기 전에 한 번 읽어 주세요. 작업 규칙만 빠르게 보려면 루트의 `CLAUDE.md`를 보세요.

---

## 1. 한 줄 요약

친구들이 **같은 가상 뉴스**를 보고 각자 사고팔면, 마감 때 결말이 공개되고 **누가 왜 앞질렀는지**를 바로 보여 주는 모바일 주식 게임입니다. 게임을 하면서 주식 용어와 투자 심리를 자연스럽게 배우게 하는 것이 목표입니다.

## 2. 누구를 위한 게임인가

만든 사람이 직접 정한 대상은 세 부류입니다.

| 대상 | 원하는 것 | 이 게임이 주는 것 |
|---|---|---|
| **주식을 처음 하는 사람** | 겁먹지 않고 해 보기 | 실제 돈·실제 기업 없이 1,000만 원 가상 자금으로 연습. 어려운 말은 눌러서 바로 뜻 확인 |
| **주식을 공부하는 사람** | 개념을 제대로 이해하기 | 가격이 움직인 이유를 bp 단위로 분해해 보여 줌. 용어 사전·퀴즈, 차트 연습실, 행동 리포트 |
| **즐기려는 사람** | 친구와 짧고 재밌게 | 5라운드 약 5분. 친구 방, 순위, 재대전. NPC 3명이 항상 함께 플레이 |

설계 판단이 갈릴 때는 **"처음 하는 사람이 이해할 수 있는가"**를 먼저 봅니다. 전문 용어를 쓸 때는 반드시 용어 사전에 넣고 링크합니다.

## 3. 핵심 아이디어: "뉴스대로 사면 이기는 게임이 아니다"

실제 시장에서 주가는 **뉴스가 좋은지 나쁜지가 아니라, 시장이 기대한 것과 실제 결과의 차이**에 반응합니다. 이 게임은 이 한 가지를 몸으로 느끼게 하려고 만들었습니다.

- 뉴스 카드는 항상 `확인된 사실 / 시장의 기대치 / 아직 남은 변수 / 주문 전 단서` 네 칸으로 나옵니다.
- 결말은 게임 시작 때 서버가 시드로 미리 정해 두고, 마감 뒤에만 공개합니다.
- "좋은 뉴스인데 주가가 내리는" 사례(기대 대비 실망)가 일부러 섞여 있습니다.
- 헤드라인만 보고 사는 전략이 이기지 못하도록 기대값을 숫자로 관리합니다(`server/src/balance.ts`, 기준은 `tests/balance.test.ts`).
  - 호재처럼 보이는 헤드라인 종목의 평균 영향: **0 근처**(기준 ±60bp, 현재 약 −29bp)
  - 주문 전 단서 방향의 평균 영향: **충분히 큼**(기준 120bp 이상, 현재 약 +180bp)
  - NPC 속보 추격형의 평균 수익률 < 분산형 평균 수익률
  - 좋은 결과의 상승 폭이 작은 사건이 많은데, 이는 "이미 기대가 주가에 반영됐다(선반영)"를 보여 주려는 의도입니다.

## 4. 게임 흐름

```
대기실 → [라운드 × N] → 최종 결과
           ├─ 뉴스 (장 시작 전. 주문 불가)
           ├─ 장중 거래 (1초 시세, 시장가 즉시 체결·지정가 예약, 중간에 장중 속보, 돌발 카드·예측)
           ├─ 정산 (장 마감. 남은 예약 자동 취소, 서버가 저장을 끝낼 때까지 '결과 집계 중')
           └─ 결과 (뉴스 결과 공개 → 종료가, 종목별 등락, 봉을 누르면 변동 근거)
```

| 모드 | 인원 | 라운드 | 뉴스/주문/결과(초) | 특징 |
|---|---|---|---|---|
| 혼자 연습 `solo` | 1 + NPC 3 | 5 | 20/90/20 | 입장 즉시 시작, 첫 라운드 5단계 따라 하기(`client/src/coach.ts`) |
| 친구 대전 `friend` | 2~8 + NPC 3 | 5 | 20/90/20 | 6자리 코드·초대 링크·QR |
| 학술제 대전 `academic` | 최대 60 + NPC 3 | 10 | 20/90/25 | 운영자 대형 화면, 결과 예측, 행동 리포트 |

설정은 `shared/rules.ts`의 `MODES`에 있습니다.

## 5. 가격 규칙 (바꾸면 테스트가 깨집니다)

```
원시 수익률 = 사건별 영향 합계 + 업종 동반 영향 + 공통 시장 변동(±50bp) + 종목 변동(종목별 최대 ±50~170bp)
업종 동반 영향 = 같은 업종 대장주의 사건 영향 × linkBeta(0.35~0.6), 반올림
제한 수익률 = 원시 수익률을 ±2,000bp로 제한
종료가     = 기준가 × (1 + 제한 수익률/10000)을 10원 단위 반올림 → 상·하한가(±20%) 적용
```

- 모든 계산은 **정수**(원, bp)로 합니다. 부동소수점 오차가 순위를 바꾸지 않게 하기 위해서입니다.
- **장중 시세**: 주문 시간(90초) 동안 종목마다 1초 간격 시세 경로가 있습니다(`intradayPath`). 경로는 시가에서 출발해 `시장 변동 + 종목 변동 + 속보 반응`에 닿는 무작위 경로(브라운 다리)이고, 흔들림은 종목 변동폭 × 1.2입니다. **사건의 최종 결과는 경로에 넣지 않고** 장 마감 때 한 번에 반영하므로, 시세로 결말을 미리 알 수 없습니다. 시드가 같으면 같은 경로입니다.
- **장중 속보**: 두 뉴스가 있는 라운드는 두 번째 뉴스가 주문 시간 한가운데 뜨고, 같은 순간 헤드라인 방향으로 `REACT_BP`(120bp, 같은 업종은 linkBeta배)만큼 튑니다. 이 반응은 종료가에 따로 더해지지 않습니다(종료가 공식은 위와 같음). 즉 반응 뒤에 산 사람은 결과 공개 때 그만큼 덜 법니다.
- **주문**: 시장가는 받은 순간의 장중 시세로 바로 전량 체결됩니다. 지정가는 기준가의 가격 제한폭 안 10원 단위로 걸어 두고, 시세가 닿으면 지정가에 체결됩니다(이미 유리하면 바로 체결). 장 마감까지 안 닿으면 자동 취소됩니다. 종목마다 예약은 하나이고 새 예약이 기존 예약을 대신합니다. 매수 예약은 지정가 × 수량 + 수수료를 묶어 둡니다.
- 참가자 주문은 시세와 종료가에 영향을 주지 않습니다. 이렇게 해야 60명이 같은 시장을 보고 공정하게 겨룰 수 있고, 1~2명이 하는 판에서 가격을 움직여 이득을 보는 길이 없습니다. 주문의 상대방은 가상 시장입니다.
- **호가창·슬리피지**: 최우선 매도 호가 = 시세, 최우선 매수 호가 = 시세 − 10원(스프레드 한 칸). 10원 간격 10단계, 단계당 평균 150만 원 × (0.6~1.4) × (1 + 0.25 × 단계), 대표 종목 1.5배(`quoteBook`). 수량은 종목·라운드·초·단계 해시로 정해져 모두에게 같습니다(시드·결말 없음). 시장가는 가장 좋은 호가부터 채우고 평균가(매수 올림, 매도 내림)로 체결합니다(`marketFill`). 가격 제한폭 밖에는 호가가 없어 하한가에서 시장가 매도는 거절됩니다. 지정가 매도는 최우선 매수 호가가 지정가에 닿으면 체결됩니다. 라운드 결과의 `slippage`는 체결가에 이미 포함된 금액(최우선 호가·시세와의 차이)을 알려 주는 정보입니다.
- **손절·익절**: 보유 종목에 손절가(시세보다 낮게)·익절가(높게)를 10원 단위로 겁니다(`setStop`, 라운드를 넘어 유지). 장중 1초마다 시세가 닿았는지 보고, 닿으면 가진 수량(매도 예약에 묶인 수량 제외) 전부를 그 순간 호가창으로 시장가 매도합니다. 장 시작 순간에도 확인하므로 결과 공개로 값이 건너뛰면 손절가보다 불리하게 팔립니다(갭). 하한가라 매수 호가가 없으면 팔지 못합니다. 다 팔면 설정이 지워집니다.
- **라운드 손익**: 종목별 손익 = 끝 수량 × 종료가 − 처음 수량 × 시가 − 산 금액 + 판 금액. 합계 − 수수료 = 평가액 변화(테스트로 고정).
- **종목**: 24개 풀(업종 6개 × 대장주 1 + 관련 종목 3). 한 판에는 대장주 6개 + 관련 종목 4개, 모두 10개가 나옵니다. 관련 종목은 이번 판 뉴스가 다루는 업종부터 고릅니다(`server/src/plan.ts` `pickStocks`). 뉴스는 대장주만 다룹니다.
- **봉·거래량**: 시가 = 라운드 시작 가격, 고가·저가 = 장중 시세와 종료가 중 최고·최저, 종가 = 종료가. `preClose`는 장 마감 직전 시세로, 여기서 종료가까지가 결과 공개로 움직인 몫입니다. 거래량은 라운드 체결 수량(참가자 + NPC)이고 정산 뒤 공개합니다.
- 수수료는 주문별 거래대금의 0.20%를 원 단위로 올립니다. 세금은 없습니다.
- 판 돈은 바로 다시 쓸 수 있고, 산 주식도 바로 팔 수 있습니다(결제일 단순화).

**실제 시장과 다른 점**(용어 사전의 "이 게임에서는" 칸에도 적혀 있음): 상·하한가 ±20%(실제 한국은 ±30%), 호가 단위 10원 고정·호가창은 가상 시장(참가자 주문이 쌓이지 않음), 세금 없음, 결제일(T+2) 없음, 주문이 시세를 움직이지 않음, 일부 체결 없음, 동시호가 단계 없음.

## 6. 구조

```
shared/    서버·클라이언트 공용. 타입, 가격·주문 규칙, 봉 계산, 용어 사전
server/    방 상태 기계, 시나리오, NPC, 리포트, WebSocket·HTTP 서버, 저장소
client/    React 모바일 화면, 학술제 대형 화면, 차트 연습실, 용어 사전
tests/     node:test. 단위·방 로직·WebSocket 2기기 대전·연습실·용어·방어 테스트
scripts/   60명 부하 검증(load), 밸런스 계산(balance)
android/   Capacitor Android 프로젝트 (같은 웹 화면을 앱으로 포장)
docs/      이 문서
```

### 서버
| 파일 | 역할 |
|---|---|
| `server/src/room.ts` | **방 하나의 순수 상태 기계.** 네트워크·DB를 모르고 시계(`now`)를 주입받습니다. 주문 검증, 정산, 화면용 `view()` 생성 |
| `server/src/plan.ts` | 시드로 게임 전체 시나리오(사건, 결말, 시장·종목 변동, 돌발 카드 라운드)를 한 번에 확정 |
| `server/src/content.ts` | 사건(Arc) 20개와 돌발 카드 10장. **결말이 들어 있으므로 클라이언트에서 import 금지** |
| `server/src/npc.ts` | NPC 3종(속보 추격형, 확인 대기형, 분산형). 사람과 같은 주문 검증을 거침 |
| `server/src/balance.ts` | 밸런스 지표(헤드라인 추종·단서 추종 기대값, NPC 성적) |
| `server/src/report.ts` | 학술제 개인 리포트(처분 효과, 군집 행동, 과잉 반응, 과신) |
| `server/src/hub.ts` | 방 목록, 100ms 타이머, WebSocket, HTTP API, 정적 파일, 남용 방지 |
| `server/src/store.ts` | 메모리 또는 PostgreSQL 저장소 |

### 데이터 흐름
1. 클라이언트가 `POST /api/rooms`로 방을 만들고 `#/room/<code>`로 이동합니다.
2. WebSocket `hello`로 입장하면 서버가 재접속 토큰을 줍니다(이름·연락처는 받지 않음).
3. 서버는 상태가 바뀔 때마다 **사람마다 다른** `RoomView`를 보냅니다. 이 뷰에는 공개된 정보만 들어갑니다. 상대 주문, 아직 공개 안 된 결말, 정산 중 새 가격은 절대 나가지 않습니다(`tests/room.test.ts`가 검사).
4. 정산은 저장에 성공한 뒤에만 결과를 공개합니다.

### 용어 사전 작성 규칙 (`shared/glossary.ts`)
- `short`는 45자 이내 한 줄. 퀴즈 보기로도 쓰입니다.
- `body`는 처음 보는 사람 기준 2~3문장, 예시 포함.
- 게임 규칙이 실제 시장과 다르면 `game`에 반드시 적습니다.
- `match`는 본문 자동 링크용 낱말입니다. 두 글자 이하 한글은 앞 글자가 한글이면 링크하지 않습니다. 다른 뜻으로도 쓰이는 낱말은 `skipAfter`로 막거나(예: '계약 체결') 자동 링크에서 뺍니다(예: '저가 수주'의 '저가').
- 실제 제도의 숫자(세율 등)는 바뀌므로 꼭 필요한 것만 쓰고, 쓰면 출처를 확인합니다.
- 새 사건을 추가했다면 그 사건의 핵심 용어가 사전에 있는지 확인합니다. `tests/glossary.test.ts`가 뉴스·카드에서 배울 수 있는 용어 수를 검사합니다.

## 8. 콘텐츠 추가 방법

### 사건(Arc) 추가
`server/src/content.ts`의 `ARCS`에 추가합니다. 사건 하나는 3단계(`step` 1~3)이고, 2·3단계는 `requires`로 이전 결말에 따라 갈라질 수 있습니다.

- `outcomes[].weight`: 결말 확률 가중치. `beat`: 시장 기대를 넘었는지.
- `signal`: 헤드라인이 주는 인상(+1/−1). NPC 속보 추격형이 이것만 보고 삽니다.
- `clueDir`: 단서가 가리키는 방향. 단서가 결말 가중치와 맞아야 "단서를 읽으면 유리"가 성립합니다.
- 영향값은 bp. 한 사건의 한 종목 영향은 대체로 ±1,200bp 이내로 둡니다.
- 모든 사건은 3단계를 채웁니다. 2단계짜리 사건이 뽑히면 뉴스가 없는 라운드가 생겨 테스트가 깨집니다.
- 헤드라인이 좋아 보이는(`signal` +1) 단계는 단서가 반대(`clueDir` −1)인 것과 같은 방향(+1)인 것을 섞습니다. 같은 방향이면 좋은 결과의 상승 폭을 작게(선반영) 잡습니다.
- 추가 후 `npm test`(밸런스 기준 포함)와 `npm run balance`를 돌립니다. 기준이 깨지면 기준을 낮추지 말고 가중치·영향값을 고칩니다.

### 돌발 카드 추가
`CARDS`에 추가합니다. 선택은 점수에 영향을 주지 않고 판단 기록과 피드백으로만 남습니다. `concept`에 쓴 말이 용어 사전에 있어야 합니다.

## 9. 지켜야 할 원칙 (협상 불가)

1. **실제 기업·인물·브랜드를 쓰지 않습니다.** 모든 기업·뉴스는 가상입니다.
2. **참가비, 유료 화폐, 현금성 보상, 송금·환전을 넣지 않습니다.** 사행성으로 보일 수 있는 요소를 만들지 않습니다.
3. 모든 화면에 "게임용 가상 정보이며 투자 조언이 아닙니다" 문구를 둡니다.
4. 이름·연락처 등 개인정보를 받지 않습니다. 재접속 토큰만 기기에 남깁니다.
5. 결말은 서버만 압니다. `server/src/content.ts`를 client에서 import하지 않습니다(테스트로 검사).
6. 가격은 참가자 주문과 무관합니다. 모두가 같은 시장을 봅니다.
7. 실제 투자 추천처럼 읽히는 문장("이 종목을 사라")을 쓰지 않습니다. 개념과 판단 과정만 설명합니다.
